# 七牛模型自动同步与 5% 加价设计

## 背景

LTS4AI 当前通过 New API 聚合上游渠道，并由 Image Studio 使用共享账号额度调用。现有文案模型 `deepseek-v4-pro` 绑定 AnyAIGC 渠道，生产调用已确认返回“该分组下无可用渠道”。现有 `SF-gpt-image-2` 渠道使用的 API Key 已在生产服务器内直连七牛 `https://api.qnaigc.com/v1/models` 验证成功。

验证时七牛 API Key 返回 74 个模型 ID，其中 73 个可在七牛模型广场结构化数据中匹配到价格和能力信息。`deepseek/deepseek-v4-pro-0813` 暂无价格元数据，按本设计保持隐藏。

## 目标

1. 将七牛作为独立 OpenAI 兼容上游接入 New API。
2. 自动同步当前 API Key 的 `/v1/models` 全部模型。
3. 仅开放同时满足“API Key 可调用、官方价格可解析、协议受支持”的模型。
4. 按七牛官方美元价格自动加价 5%，统一扣除 LTS4AI 账号额度。
5. 保留 `SF-gpt-image-2` 及其现有渠道。
6. 停用并隐藏其他旧渠道和旧模型，但不永久删除配置。
7. 服务启动时同步一次，此后每 24 小时同步一次，并提供管理员手动同步入口。
8. 同步失败时继续使用上一次成功快照，不中断现有用户调用。

## 非目标

- 不修改 Image Studio 的账号体系、匿名访问或历史记录合并逻辑。
- 不把七牛 API Key 返回给浏览器、Bridge 或用户。
- 不删除旧渠道、旧价格配置或旧模型元数据。
- 不把当前仅支持文本输出的七牛模型放入 Image Studio 生图模型列表。
- 不在本期实现七牛 Anthropic 协议；统一使用 OpenAI 兼容协议。

## 方案选择

采用 New API 内原生七牛同步任务，不使用 Bridge 写数据库，也不使用服务器 Cron 直接执行 SQL。

原因：

- New API 已有系统任务、跨实例租约、任务历史、渠道缓存刷新和管理后台框架。
- New API 已有动态计费表达式，可准确覆盖阶梯价、缓存价和输入/输出差价。
- Bridge 继续保持对 New API 数据库只读的最小权限。
- 所有渠道、能力和价格变更可在同一进程内原子提交并刷新缓存。

## 数据来源

### 可调用模型

- 请求：`GET https://api.qnaigc.com/v1/models`
- 鉴权：专用七牛渠道中保存的 API Key。
- `data[].id` 是当前密钥可调用模型的唯一准入范围。

### 官方价格和能力

- 来源：`https://www.qiniu.com/ai/models` 的结构化模型数据。
- 读取字段：模型 ID、输入/输出模态、支持协议、退役时间、`pricing_rules_v2`。
- 价格优先使用 `unit_price_usd`，不自行维护人民币汇率。
- 如果模型广场结构变化、模型缺失、价格字段缺失或单位不支持，该模型不会开放。

模型列表与价格数据必须在同一次同步中成功读取和校验。任一数据源整体失败时，本次同步不修改生产状态。

## 渠道设计

新增一个受管渠道：

- 名称：`Qiniu AI Managed`
- 类型：OpenAI 兼容渠道
- Base URL：`https://api.qnaigc.com`
- 分组：`default`
- 标签：`qiniu-managed`
- 模型：由同步任务维护，管理员不手工编辑
- Key：首次部署时在服务器内部从现有 `SF OpenAI Upstream` 渠道复制；不进入代码、日志或聊天记录

`SF OpenAI Upstream` 继续只提供 `SF-gpt-image-2`。同步任务不得修改该渠道的 Base URL、模型映射或价格。

## 模型准入与能力分类

模型只有同时满足以下条件才会加入七牛受管渠道：

1. ID 存在于七牛 `/v1/models` 返回值。
2. ID 存在于七牛模型广场结构化数据。
3. 至少存在一条可解析的 `pricing_rules_v2`。
4. 输出模态为 `text`。
5. 支持 OpenAI 协议。
6. 未到退役时间，且未被七牛标记为不可用。

当前七牛密钥返回的可定价模型全部属于文本输出。它们进入文案模型列表；支持图片、视频或音频输入的模型仍属于文本输出模型，不进入生图列表。

`SF-gpt-image-2` 继续声明 `image_generation` 和 `image_edit` 能力。

缺价格模型如 `deepseek/deepseek-v4-pro-0813` 记录为 `hidden_unpriced`。后续价格出现后自动开放，无需手工操作。

## 价格转换

统一加价系数为 `1.05`，通过环境变量配置，默认值为 `1.05`。生产环境固定配置为 1.05。

七牛价格中的 `unit_price_usd` 表示每 `unit_size` 个单位的美元价格。转换为 New API 动态计费表达式的每百万 token 系数：

`coefficient = unit_price_usd × (1,000,000 / unit_size) × 1.05`

字段映射：

- `input` 或 `ncache` → `p`
- `output` → `c`
- `cache` → `cr`
- 输入范围条件 → `len`
- 输出范围条件 → `c`

规则按七牛返回顺序编译为带 `tier()` 的嵌套条件表达式。范围按左闭右开处理，最后一个开放上界规则作为兜底。表达式在写入前必须通过 billingexpr 编译器验证。

示例：七牛每 1,000 token 输入价 0.006 美元、输出价 0.024 美元时，5% 加价后的表达式系数分别为 6.3 和 25.2：

`v1:tier(qiniu_0, p * 6.3 + c * 25.2)`

免费模型的官方价格为零时仍保持零价，不人为添加最低收费。

以下价格结构暂不开放模型：

- 缺少美元价格；
- 未知计费单位；
- 无法转换的按次、按秒或复杂媒体计费；
- 价格规则范围重叠、缺口或无法确定兜底；
- 动态计费表达式编译失败。

## 同步算法

每次同步按以下顺序执行：

1. 获取七牛 `/v1/models`。
2. 获取并解析七牛模型广场结构化数据。
3. 按模型 ID 取交集并执行准入检查。
4. 为每个模型生成动态计费表达式并进行编译验证。
5. 生成完整候选快照：渠道模型、模型元数据、能力、计费表达式和隐藏原因。
6. 在数据库事务中写入候选快照和同步状态。
7. 事务成功后更新渠道 abilities、刷新渠道缓存、价格缓存和模型元数据缓存。
8. 记录新增、恢复、下架、价格变化、隐藏和失败统计。

同步采用“完整快照替换”，而不是在旧列表上只追加：

- 新出现且可定价的模型自动开放。
- 已从 `/v1/models` 消失的七牛模型从受管渠道移除并隐藏。
- 价格暂时缺失的模型从受管渠道移除并标记隐藏。
- 再次出现且价格恢复的模型自动恢复。
- 同步只管理带 `qiniu-managed` 所有权标记的配置，不覆盖人工模型或 `SF-gpt-image-2`。

任何网络、解析、校验或事务错误都会使整次同步失败；生产继续使用上一成功快照。

## 任务调度与管理入口

新增系统任务类型 `qiniu_model_sync`：

- New API 启动后立即尝试调度一次。
- 周期为 24 小时。
- 使用现有系统任务租约，避免多实例重复执行。
- 管理后台提供“立即同步七牛”按钮。
- 手动同步与定时同步互斥；已有任务运行时返回冲突提示。
- 系统任务详情展示模型总数、开放数、隐藏数、新增数、下架数、价格变化数和失败原因。

生产配置：

- `QINIU_MODEL_SYNC_ENABLED=true`
- `QINIU_MODEL_SYNC_INTERVAL_HOURS=24`
- `QINIU_MODEL_PRICE_MARKUP=1.05`
- `QINIU_MANAGED_CHANNEL_TAG=qiniu-managed`

## 旧渠道和旧模型处理

首次七牛同步和代表性真实调用验收成功后执行切换：

1. 保持 `SF OpenAI Upstream` 启用，并将其公开模型限制为 `SF-gpt-image-2`。
2. 保持 `Qiniu AI Managed` 启用。
3. 将其他旧模型渠道状态改为停用。
4. 将其他旧模型元数据状态改为隐藏，确保模型广场不展示。
5. 不删除渠道行、Key、模型映射、倍率、计费表达式或历史日志。
6. 切换前生成包含渠道状态和模型元数据状态的数据库备份。

公共 `/v1/models`、LTS4AI 模型广场和 Image Studio 模型列表最终只包含：

- 七牛受管渠道中当前开放的文本模型；
- `SF-gpt-image-2`。

## 安全

- API Key 只保存在 New API 渠道配置中。
- 同步日志不得输出 Key、Authorization 头、完整 Cookie 或用户 grant。
- 错误信息必须经过清洗，不回显七牛响应中的敏感字段。
- 手动同步入口只允许管理员访问，并记录管理审计。
- Bridge 不增加数据库写权限。
- 价格页面抓取设置响应大小、连接时间和总时间限制，拒绝异常大响应或缺少预期结构的数据。

## 可观测性

同步任务记录：

- 开始和完成时间；
- `/v1/models` 模型数；
- 价格元数据模型数；
- 开放、隐藏、新增、下架、恢复、价格变化数量；
- 隐藏原因分类；
- 上次成功同步时间和当前快照版本；
- 不含凭据的失败摘要。

连续同步失败时使用现有通知机制告警，但不清空当前模型或价格。

## 测试

### 单元测试

- 七牛 `/v1/models` 解析和去重。
- 模型广场结构化数据解析。
- 模型交集、缺价格隐藏、退役隐藏和协议过滤。
- 平价、缓存价、阶梯价和 5% 加价表达式生成。
- 未知单位、重叠范围、价格缺失和表达式编译失败。
- 完整快照 diff：新增、下架、恢复和价格变化。

### 集成测试

- 事务失败不改变现有渠道模型和价格。
- 同步成功后 abilities、模型元数据和价格缓存刷新。
- 定时任务与手动任务租约互斥。
- 管理后台手动同步和任务详情。
- 公共 `/v1/models` 只返回七牛开放模型与 `SF-gpt-image-2`。
- Bridge 将七牛模型归类为文本能力，将 `SF-gpt-image-2` 归类为生图能力。

### 生产验收

- 使用生产 Key 同步但不输出 Key。
- 对一个普通文本模型和一个阶梯价模型执行短文本请求。
- 验证响应成功、渠道命中七牛、额度按 5% 加价后扣除。
- 验证 `SF-gpt-image-2` 生图仍成功。
- 验证旧模型不再出现在 LTS4AI 和 Image Studio 模型列表。
- 验证容器健康、零重启且日志无凭据泄漏。

## 发布顺序

1. 备份 New API 数据库和生产配置。
2. 部署包含七牛同步器的新版本，但暂不停用旧渠道。
3. 创建七牛受管渠道并在服务器内部复制现有 Key。
4. 运行手动同步并审查模型数、隐藏数和价格表达式。
5. 执行代表性文本调用和额度核算。
6. 停用隐藏旧渠道和旧模型。
7. 验证 LTS4AI、Bridge 和 Image Studio 列表及真实调用。
8. 开启 24 小时定时同步。

## 回滚

回滚不依赖恢复代码提交：

1. 禁用 `qiniu_model_sync` 定时任务。
2. 停用 `Qiniu AI Managed` 渠道。
3. 从切换前备份恢复旧渠道状态和旧模型元数据状态。
4. 刷新渠道、模型和价格缓存。
5. 保持 `SF-gpt-image-2` 渠道不变。

七牛同步写入的模型元数据和价格配置可保留为隐藏状态，不需要物理删除。

## 验收标准

- 定时同步间隔为 24 小时，启动时可立即同步，管理员可手动触发。
- API Key 返回且价格可解析的七牛文本模型自动开放。
- 无价格或不支持的模型保持隐藏。
- 所有七牛价格准确转换为官方美元价乘 1.05。
- 同步失败不影响上一次成功快照。
- 公共模型列表只包含七牛开放模型和 `SF-gpt-image-2`。
- 旧渠道停用隐藏但可完整恢复。
- 用户继续使用统一 LTS4AI 额度，无需配置七牛 Key。
